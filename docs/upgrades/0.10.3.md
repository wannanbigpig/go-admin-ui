# 0.10.3 发布与部署说明

从 v0.10.2 升级。本版本包含 v0.10.2 的全部导出、通知与手机端修复，更新 `follow-redirects` 和 Vite 的安全补丁。v0.10.2 的 Node.js CI 在生产依赖安全扫描中失败，其历史 Tag 保留，推荐使用本版本。

## API 变更

本版本没有修改业务接口、字段、错误码、认证、权限、配置结构或数据库，继续支持后端 `>=0.10.0 <0.11.0`，推荐配套后端 v0.10.3。无需 migration、API 权限同步或任务定义同步；不要执行 `init-system`。

`follow-redirects` 从 1.16.0 更新至 1.16.1，修复 [GHSA-q3jh-wrc6-jgq8](https://github.com/advisories/GHSA-q3jh-wrc6-jgq8) 和 [GHSA-8r9p-f939-6h3c](https://github.com/advisories/GHSA-8r9p-f939-6h3c)。Vite 从 8.3.0 更新至 8.3.3，修复 [GHSA-587h-7wmj-h5pm](https://github.com/advisories/GHSA-587h-7wmj-h5pm)。升级仅涉及依赖补丁和构建工具，不引入新的业务配置。

## 升级顺序

1. 确认前后端双向兼容范围，记录当前部署版本、静态资源及 API 配置；从 v0.10.1 直接升级时，同时参考 [0.10.2 升级说明](0.10.2.md)。
2. 使用 v0.10.3 正式资源包并校验 SHA-256；自行构建时使用项目声明的 pnpm 12.4.1 和 `pnpm install --frozen-lockfile`，完整采用本版本锁文件。
3. 上传到独立发布目录并原子切换入口，保留上一版完整目录用于回滚，不混用不同版本 HTML 与资源。
4. 核对 `build-info.json` 中的版本、commit、`dirty=false` 和 `channel=tagged`；在目标环境验证登录、动态菜单、通知与导出流程。

## 回滚限制

没有数据库或持久化数据变更，可在前后端兼容范围内回退完整静态资源和部署配置。回退到 v0.10.2 或更早版本会恢复本次依赖安全问题；优先向前修复，不将回退作为长期方案。已发布 Tag 与同名资源不覆盖。

## 验证

执行 `pnpm audit --prod --audit-level high --registry=https://registry.npmjs.org`、发布规则测试、Lint、类型检查、完整单元与浏览器回归、生产构建及差异检查。正式 Tag 的干净检出执行 `pnpm run check:release --tag v0.10.3`。

目标环境仍需核对登录、续期、权限菜单、通知筛选、任务完成后的导出下载以及 390px 窄屏操作。本地 Mock 与 GitHub CI 不代表真实后端、Worker、对象存储或目标服务器已联调验收。
