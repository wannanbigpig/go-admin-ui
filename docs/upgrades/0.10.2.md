# 0.10.2 发布与部署说明

从 v0.10.1 升级。本版本修复导出、通知列表、手机导航和中英文展示问题，并补齐对应 Mock 与回归测试。

## API 变更

继续支持后端 `>=0.10.0 <0.11.0`，推荐配套已发布的后端 v0.10.3。导出详情调用已有的 `GET /admin/v1/system/export/detail`，以 `public_id` 查询最新记录；没有新增或修改后端接口、请求字段、错误码、权限或认证策略。

本版本没有数据库、菜单权限、任务定义或配置结构变更，无需执行 migration、API 权限同步或任务定义同步。不要为升级前端执行 `init-system`。

## 升级顺序

1. 记录当前前后端版本与部署配置，保留当前静态资源及完整发布目录作为回滚备份；确认后端也声明兼容管理端 0.10.2。
2. 从 v0.10.2 GitHub Release 获取静态资源包并校验 SHA-256；需要自定义 API 地址时，在干净源码中按目标环境配置重新构建，不直接沿用本机环境文件。
3. 将完整静态资源上传到新的发布目录，原子切换入口，避免新 HTML 与旧资源混用。
4. 验证登录、动态菜单、通知筛选和导出详情。手机端使用顶部导航按钮打开菜单，桌面侧栏的展开偏好保持独立。

## 回滚限制

本版本不修改后端及持久化数据，可在确认后端双向兼容范围后回退至此前实际部署的 v0.10.1 完整静态资源与配置。回滚会恢复旧版导出详情、通知竞态和手机布局问题；不需要回滚数据库或撤销权限同步。

## 验证

发布前执行 `pnpm run check:release`、`pnpm run test:release`、Lint、类型检查、单元测试、浏览器回归和生产构建。正式 Tag 的干净检出执行 `pnpm run check:release --tag v0.10.2`，并核对 `dist/build-info.json` 的版本、提交及 `dirty=false`。

目标环境验收：快速切换通知筛选不被旧请求覆盖；打开导出详情后等待任务完成可获得结果文件；状态卡片数字与筛选记录一致；在 390px 宽度下导航、筛选和详情完整可用；英文日期与数量不出现中文残留，卡片支持 Enter / Space。Mock 和本地浏览器结果不代表真实后端、Worker 或对象存储已经完成联调。
